**成本是可測量邊際的約 50 倍。** 這個缺口不是調參能補的。

### 2.2 根因：`rank_pct` 標籤選錯了股票

- 標籤獎勵「贏過中位數的機率」→ 偏好**低波動**股：`Spearman(score, vol20)` = −0.48～−0.57，
  前 20 名落在波動百分位 0.24～0.31，55–69% 來自最低波動分位。
- 但超額報酬**右偏**（skew 1.4–1.9，各波動分位中位數皆為負），贏家住在**高波動**股：
  平均超額隨波動分位由 −0.33% 升到 +0.31%／10 日。
- 最傷的一組數字：**實際超額報酬前 5% 的股票帶走 46% 的橫斷面變異與 41% 的正超額質量；
  而分數前 5% 只帶走 3.4% 的變異、約 0% 的正超額質量。**
- 模型真正有效的是**避開**（最低分桶 −0.13～−0.26%／10 日）——純多頭 top-20 結構上用不到這一側。

### 2.3 目標函數可改（已有現成證據）

`ml_net_h20`（`cost_adjusted_return` 標籤，模型 `lgbm_net_h20_20260225_9a575e97`）把傾斜翻到最高波動分位
（72% 的選股），top-20 超額升到 **+0.55%／10 日**（rank 模型的 7 倍，約等於一次來回成本），
但它維持週頻（周轉 2,768%），所以 1× Sharpe 只有 0.13。**目標函數只動毛利，不動成本。**

## 4. 環境與操作

```bash

  TWQUANT_PG_DSN="postgresql://twquant:twquant@localhost:5433/twquant" \

```

- **PG**：docker 容器 `twquant-pg-1`，`postgresql://twquant:twquant@localhost:5433/twquant`。
- **Docker 崩潰後起不來**（本週發生三次，同一根因）：崩潰留下的 `userAnalyticsOtlpHttp.sock` 是無法存取的
  reparse point。修法＝停光程序 + `wsl --shutdown` → **移走整個 `%LOCALAPPDATA%\Docker\run`** → 新建空目錄 → 啟動。
  現成腳本 `scratchpad/fix_docker4.ps1`（10 秒就緒）。
  **寫這類腳本的兩個坑**：用 Python 寫 `.ps1` 時 `'Docker\run'` 的 `\r` 會變成歸位字元；
  PowerShell 5.1 以 ANSI 讀 `.ps1`，檔內中文會被打亂成語法錯誤——**訊息一律用英文**。
- **記憶體預算**：主機 32 GB，一次只能跑「一個重運算 + 一條抓取」。IC 報告約 6 GB、6 分片物化、pg_dump、
  FinMind 抓取同時開會 OOM（2026-09-03 02:43 就是這樣把 Docker 弄倒的）。
