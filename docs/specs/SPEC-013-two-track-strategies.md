- §0 可用來**決定研究方向**（把兩軌分開、改宇宙與加權）

因此「品質資訊已被模型吸收，所以 T-119 的濾網才沒效」只是**待測假說**，
不是已確立的機轉。12 個特徵仍可能間接帶有品質資訊，但那需要另外量測。

**結論（方向性，非最終裁決）**：落後由兩塊組成，量級差一個數量級。

- **① 市場結構**：等權廣宇宙在 2024–25 就輸 0050 三十幾個百分點。這與選股無關。
- **② 模型選股**：平均約 −1pp/年，年度間 ±8pp 亂跳、正負號會翻，統計上是零。

現況策略的持股全為小型股（貢獻前後各 10 名皆是），整份回測資料中
`2330`／`2317`／`2454`／`2308`／`3711`／`2382` 出現 **0 次**。
它事實上已經是一個小型股策略，卻被拿去跟市值加權指數比。

**本規格的設計原則因此是：把「兩件不同的事」分成兩軌，各自配正確的基準，
而不是繼續調一個同時做不好兩件事的策略。**

### 2.1 已查證可直接用、不需新增的（省得執行者重造）

- `combine: rank_avg` **已實作**，且 `signed = weight × direction` 已在
  `build.py` 完成——`direction=-1` 的因子（如 `price.vol_20d`）會自動反向。
  YAML 裡的 `weight` 一律填**正數且加總為 1**，不要自己加負號。
- `price.mom_60d` 與 `price.vol_20d` 都吃 `params.window`，
  `lookback_days` 僅為 registry 中繼資料、`compute` 不使用，故
  `params: {window: 60}` 可用。
- `fundamental.log_market_cap` 已註冊（`ln(收盤 × 股本 ÷ 面額)`）。
- CLI 已有 `--cost-scale 0`（零成本反事實）與 `capacity` 指令。
- `report_bundle.py` 已可用 argv 指定策略／輸出／成本檔。

### 2.2 一個已知的權重缺陷（T-123 必須一併修）

`build.py` 最後套 `max_weight_per_stock` 用的是
`min_horizontal(target_weight, cap)`——**只截頂、不重新歸一**。
等權時因為 `1/n ≤ cap` 恰好無影響，但**市值加權一旦截頂就會漏曝險**
（總權重 < 1，等於偷偷持有現金）。T-123 必須改成「截頂後把剩餘權重
按比例重分配給未觸頂者，反覆至收斂」，並補測試證明總權重 = 1（容差 1e-9）。

收斂的終止條件要寫死，不得靠迴圈次數猜：**當某一輪沒有任何新的部位觸頂即停止**。
另需處理退化情形——若 `top_n × max_weight_per_stock < 1`（例如 30 檔 × 2% = 0.6），
權重數學上湊不到 1，此時**必須 raise 並指出兩個數字**，不得靜默回傳低於 1 的總權重
（黃金規則 5）。

### 2.2.1 `weighting` 的列舉值（**執行者最容易卡住的地方**）

`StrategyConfig.weighting` 目前是 `Literal["equal", "score_prop", "inv_vol"]`。
本規格要用的 `score_pow` 與 `mktcap` **不在這個列舉裡，pydantic 會直接擋下**。
T-123 必須：

1. 把 Literal 擴充為 `["equal", "score_prop", "score_pow", "inv_vol", "mktcap"]`
2. **`score_prop` 實作為 `score_pow` 的 p=1 特例**（兩者數學上同一件事，不寫兩份）
3. `inv_vol` **維持未實作**，但錯誤訊息要改成明確的「尚未實作，見 SPEC-013 §2.2.1」，
   而不是現在指向 T-017 備註的舊訊息。本規格用不到它，不得為了「順手」而實作
   （CLAUDE.md §7 禁止範圍外重構）。
4. `score_pow` 的 `p` 從配置注入。`SelectionConfig` 那種「刻意無預設」的做法在此**不適用**——
   `p` 有自然預設 1（＝`score_prop`）。但 §3.2 的 L4 與 §5 的 B 軌都明確用 p=2，
   YAML 必須顯式寫出，不得依賴預設值。

#### 加權契約（R3／R4／R12 修訂後的完整定義；歧義即實作錯誤）

**(a) `score_pow` 的分數平移。** `rank_avg` 的實作是「正向百分位總和 **減去** 負向
百分位總和」，故四因子分數落在 [−0.25, +0.75]，**必然出現負分**；`zscore_weighted`
更是如此。`score^p` 對負分無意義（p=2 時 −0.25 與 +0.25 得到相同權重，方向反轉）。

事前寫定，**無條件套用**（不是「有負分才平移」——條件式會讓權重取決於當日是否恰好
有負分，同一策略在不同日子適用不同公式）：

```text
shift = 當日**全宇宙**分數的最小值        # 非「選中名單」的最小值
w_i  ∝ (score_i − shift) ** p
```

母體用全宇宙而非選中名單，是因為選中的都是高分股，用它們的最小值會把名單中最後一名
壓成權重 0（等於少持一檔）。全宇宙最小值則讓入選者都保有實質正值。

**零分母**（全宇宙同分，`Σ(score−shift)^p == 0`）→ **退化為等權**，不得除以 0，
也不得 raise：橫斷面全同分是合法的資料狀態（如全部因子缺值後補同值）。

**這是「受外部啟發的本地變體」，不是 finlab 規則的複製**（R11）。原文用低波動的
**正向**百分位、分數全為正、無需平移；我們的框架以 signed weights 表達方向，兩者排序
相同但**相差一個常數**，平方後權重不同。差異必須在報表的方法論表中列出。

**(b) `mktcap` 加權用線性市值，不是 log。** `fundamental.log_market_cap` 回傳
**ln(市值)**，權重必須用 `exp(value)`；直接按 log 值比例會把 1.5e6 與 4e3 的差距
壓成 14.2 比 8.3。且**不得套用該因子的 `direction=-1`**——那會讓大小市值反轉。
（排名用途不受影響：ln 單調，故 T-121 的 `_mktcap_gate` 直接用原值排序是對的。）

**(c) 截頂重分配必須在 overlay 之前。** 現行順序是 `_weight` → overlays → 截頂。
若在**最後**把總權重歸一到 1，會把 `breadth` 這類 overlay 刻意壓低的曝險補回去，
改變既有策略的行為。故：**截頂與重分配一律在 `_weight` 內完成**，overlay 之後
不再歸一，overlay 設定的總曝險是最終值。

**(d) 可行性檢查用「實際入選檔數」，不是設定的 `top_n`。** 設定選 40 檔不代表當日
有 40 檔通過濾網。判準是 `len(picked) × max_weight_per_stock < 1 − 1e-9` 時 raise，
訊息須同時指出**實際檔數**、設定的 `top_n` 與上限值。用 `top_n` 檢查會在
「設定 40、實際只剩 10 檔」時放行，然後產出一個總曝險最多 50% 的組合而不報錯。

**(e) 缺因子的股票。** `rank_avg` 對**存在的列**求和，故缺少負向因子（如低波動）
的股票**拿不到那個負分、分數虛高**（R12）。四因子配置必須要求**四項齊全**才入選；
T-123 在 `_weight` 之外另立一條前置檢查，於 `build_targets` 中在選股前剔除
因子不齊者，並在錯誤訊息中報出當日被剔除的檔數。

### 2.3 一個刻意的設計選擇：市值篩用「排名」而非「絕對值」

T-120 已指出既有濾網的隱患：`min_adv_twd: 30_000_000`、`min_price: 10.0` 是**絕對門檻**，
在長歷史上會漂移（3,000 萬 TWD 在 2005 年與 2026 年是完全不同的門檻）。

因此 T-121 新增的市值篩一律用**排名**（`mktcap_rank_max` / `mktcap_rank_min`），
定義上不隨年代漂移。本規格的短窗口（2022-07~2026-02）沿用既有絕對門檻以維持與
現況可比；**長窗口重跑（T-130）必須先解 T-120**，否則早期宇宙會被砍到不成比例地小。

## 3. 控制組階梯（**最先做**，回答三個問題）

在做任何新策略之前先跑這個。它用**最小的計算量**回答三個未決問題，
而且結果會直接決定 A／B 兩軌該怎麼設計。

### 3.1 三個問題

1. **我們的資料／成本／窗口有沒有問題？**（若簡單策略也垮，ML 就不是元凶）
2. **宇宙構造值多少？**（基本面篩 vs 現在的純流動性篩）
3. **40 檔 vs 20 檔值多少回撤？**

### 3.2 階梯設計（每一階相對前一階**只改一件事**）

| 階 | 配置檔 | 相對前一階的唯一變更 | 回答 |
|---|---|---|---|
| **L0** | `ml_net_h20_m.yaml`（既有，不動） | — 現況基準 | 基準 |
| **L1** | `ladder_l1_n40.yaml` | `selection.top_n: 20 → 40` | **Q3** |
| **L2** | `ladder_l2_rev.yaml` | 宇宙加營收篩（見 §3.4） | **Q2** |
| **L3** | `ladder_l3_simple.yaml` | 訊號 ML → 四因子（見 §3.5） | **Q1**（條件版） |
| **L4** | `ladder_l4_wt.yaml` | `weighting: equal → score_pow`（p=2） | 權重貢獻 |
| **X1** | `ladder_x1_simple20.yaml` | **= L0 但只換訊號為四因子**，其餘逐字同 L0 | **Q1**（無條件版） |

**為什麼要 X1**：階梯是累積的，L3 的改善是「在 L1+L2 之上」的條件效果。
X1 把訊號單獨換掉、其他全部維持 L0，才能回答「ML 對比簡單因子，本身值多少」
而不與檔數／宇宙糾纏。這一格只多花一次回測，但少了它整個 Q1 無法下結論。

### 3.3 每一階跑兩次

```bash
# 正常成本
uv run --all-groups python -m twquant backtest --strategy configs/strategies/<階>.yaml --start 2022-07-01 --end 2026-02-28
# 零成本反事實
uv run --all-groups python -m twquant backtest --strategy configs/strategies/<階>.yaml --start 2022-07-01 --end 2026-02-28 --cost-scale 0
```

**前置：`backtest` 目前不保存曲線**（R8）。它只印指標、把純量寫進 `research_log`，
`BacktestResult` 的 `equity`／`ledger`／`unfilled` 全部丟棄。照上面跑完 12 次之後，
§3.6 所需的「既有曲線」根本不存在。故 **T-127 的前置是一個統一結果包**：
一次 run 落地曲線、ledger、未成交、日期、完整配置與資料指紋，之後的分段與報表
都從同一份 artifact 產生，不重跑。落地由 CLI 或 `reporting/` 負責（黃金規則 10）。

**成本情境是三個不是兩個**：1×、0×、**1.5×**。D-038 §5 明文要求
「1.5× 成本後 CAGR／Sharpe 仍 > 0」，只跑 1× 與 0× 無法宣稱完成晉升驗收。
1.5× 一律用 `--cost-scale 1.5`（等比縮放整個成本模型），**不是**只改滑價係數——
兩者不同，必須指名。A 軌 §4.3 的「滑價加倍」同樣改用 `--cost-scale`，
以免「加倍」指涉不明。

### 3.4 營收篩的定義（照 finlab 公開參數，外部先驗，**不得調整**）

- 連續 3 個月營收年增為正
- 且當月營收年增介於 **+10% ~ +150%**

上限 150% 是刻意的：排除減資、合併、基期異常造成的假成長。
這三個數字是外部先驗（他人公開文章），**不是我們配適出來的**，
因此不佔我們的搜尋額度。任何人不得因為「跑出來不好看」而改動它們。

### 3.5 四因子的定義（同樣是外部先驗，**不得調整**）

```yaml
combine: rank_avg
signals:
  - {factor: fundamental.revenue_yoy, weight: 0.25}
  - {factor: price.mom_60d,           weight: 0.25}
  - {factor: fundamental.roe,         weight: 0.25}
  - {factor: price.vol_20d,           weight: 0.25, params: {window: 60}}
```

四個因子等權相加百分位排名。`price.vol_20d` 的 `direction=-1` 會由框架自動處理
（低波動得高分），**不要在 YAML 裡寫負權重**——那會讓 `_weights_sum_to_one` 驗證失敗。

### 3.6 窗口的處理（不需額外回測）

從既有的權益曲線切子區間即可，**不要重跑**：

- 前段 `2022-07-01 ~ 2023-12-31`（廣度正常期）
- 後段 `2024-01-01 ~ 2026-02-28`（權值股集中期）

若某階的結論在兩個子區間**符號相反**，該階的結論即標記為「窗口相依，不可外推」，
並在報表中明說。這是本專案目前最大的未知，不得用單一數字掩蓋。

**長窗口（2005 起）的重跑列為 T-130，本階段不做。**
注意 T-130 **不能照抄本階梯**（R9）：L0／L1／L2 都依賴 pin 住的 ML 歷史分數，
而價格回補**不會**產生更早年份的 OOS 分數；拿 2026 年訓練的模型回推 2005~2020，
會把訓練期內的資料當成樣本外。故 T-130 只有兩種合法形態：

1. 早期只跑**非 ML 候選**（L3／L4／X1 與兩軌），明說沒有重跑完整階梯；或
2. 另行授權重訓：需先確認歷史財報／特徵覆蓋、最短訓練暖身期，
   並以 purged walk-forward 重新產生各年份的 OOS 分數。

且「增加年份」只能增加樣本長度，**不保證 DSR 達標**，也不能把已反覆檢視過的
開發期重新宣稱為最終樣本外。

### 3.7 判讀規則（事前寫定，防止事後找故事）

**這個階梯能識別的是「每一步在當前條件下的增量」，不是普遍因果**（R1）。
以下三種說法都**不成立**，禁止寫進任何結論：

- 「X1 也輸基準 → 問題不在 ML」。反例：基準 +10%、ML −10%、四因子 +5%——兩者都輸基準，
  但 ML 仍比四因子差 15pp。兩個都輸不能替任何一個開脫。
- 「零成本仍輸 → 成本不是元凶」。正確說法只到「**移除成本仍不足以解釋全部落後**」；
  成本仍可能是重要拖累。
- 「B 軌贏了 → 架構貢獻大於訊號貢獻」。B1／B2 同時換了宇宙、檔數、訊號與權重，
  單一比較無法歸因到其中任何一項。

#### 每個配對比較的 estimand（跑之前寫定）

執行者**只需填表，不需下結論**。每一階與其**前一階**配對比較，回報三個量：

| 量 | 定義 |
|---|---|
| ΔCAGR | 兩者在**共同交易日**上的年化報酬差 |
| ΔMDD | 最大回撤差（正 = 改善） |
| Δ日報酬 | 逐日配對差的平均，**以月為區塊**估計不確定性 |

不確定性一律用**月度區塊**，不得把每日報酬或重疊持有期當獨立樣本
（持股期 20 日，日報酬高度自相關，直接算日頻 t 值會嚴重高估顯著性）。

回報格式為「點估計 ± 區塊標準誤」，並允許且鼓勵填入
**「未能區分」**——那是合法且常見的結果，不是失敗。

#### 固定候選，不隨結果變形（R7）

§4／§5 的 YAML 是**固定候選**，不是條件模板。階梯結果**不會**自動改寫它們
（先前版本寫「L1 過門檻就兩軌都採 40 檔」，那等於在看到結果之後改候選，
是事後選擇）。若讀完階梯確實想改 A／B 的檔數或濾網，**另開裁決、另計 trial**，
不得把新配置仍稱作原候選。

另注意：L1 的檔數效果是在**廣宇宙**上量到的，不能直接外推到 A 軌的小型股宇宙
或 B 軌的大型股宇宙——不同宇宙的橫斷面分散度不同。

## 4. Track A — 小型飆股

### 4.1 意圖

明確承認這是高波動、低容量、追求右尾的策略。**它的目標不是打敗 0050。**

### 4.2 配置 `configs/strategies/track_a_smallcap.yaml`

```yaml
name: track_a_smallcap
description: A 軌小型飆股：小市值 × 動能 × 營收加速 × 量能（未經部署裁決，勿用於實盤）
trial_scope: smallcap_momentum   # 不帶 bt: 前綴——框架會自己加（R5）

universe:
  markets: [TWSE, TPEX]
  mktcap_rank_min: 101        # 排除市值前 100 大（T-121 新增欄位）
  min_adv_twd: 30_000_000     # 小型 + 沒量 = 不可交易，流動性門檻不得放寬
  min_price: 10.0
  min_revenue_yoy: 0.10       # T-122 新增；與 §3.4 同一組先驗
  max_revenue_yoy: 1.50
  min_revenue_streak: 3

combine: rank_avg
signals:
  - {factor: price.mom_60d,             weight: 0.30}
  - {factor: fundamental.revenue_accel, weight: 0.30}
  - {factor: volume.turnover_z_20d,     weight: 0.20}
  - {factor: fundamental.roe,           weight: 0.20}

selection: {method: top_n, top_n: 15}
weighting: equal
rebalance: {schedule: monthly, day: MON, execution: next_open}
max_weight_per_stock: 0.10
overlays: []
```

`fundamental.roe` 在此的角色是**護欄不是選股**：finlab 的動能文實測
「ROE 品質篩是動能策略的轉折點（年化 11.5% → 39.6%）」，其機轉是砍掉動能的
投機尾巴。權重 0.20 是刻意壓低的，因為我們自己的 T-119 實測顯示
硬濾網會造成排序稀釋——這裡用**軟排名**而非硬門檻，正是為了取兩者之長。

### 4.3 A 軌的強制檢查

1. **容量**：必須跑 `python -m twquant capacity --strategy <path>` 並在報表中列出
   可承載資金上限。小型飆股策略的容量若低於 1,000 萬台幣，必須在報表**紅字**標示。
2. **成本敏感度**：除 `costs.yaml` 外，另跑滑價加倍情境。finlab 那篇「打敗 0050」
   的四因子策略在單邊滑價 0.5% 時年化從 29.45% 掉到 22.64%、**反而輸給 0050**——
   小型股策略的結論對滑價假設極度敏感，不做這個檢查等於沒做。
3. **未成交**：`res.unfilled` 中 `reason=limit_up` 的比例必須列出。飆股策略買不到
   漲停板是系統性偏誤，若 > 5% 則整個回測的報酬需標註為高估。

## 5. Track B — 穩健打敗大盤（兩個版本）

### 5.1 為什麼需要改架構，而不是換因子

§0 的診斷已證明：等權 20 檔小型股組合**在結構上就不可能追上市值加權的 0050**。
0050 裡台積電約 57%，我們的 `max_weight_per_stock` 是 5%。
這不是選股問題，是加權與宇宙的問題。**要打敗 0050，必須先能「像」0050。**

因此 B 軌的兩個版本都改變**宇宙與加權**，而不是繼續換因子。

### 5.2 B1「大型股增強」`track_b1_large_enhanced.yaml`

貼著 0050 走，靠因子傾斜賺幾個百分點。Beta 應接近 1、追蹤誤差小。

```yaml
name: track_b1_large_enhanced
description: B1 大型股增強：市值前 100 大選 30 檔、市值加權（未經部署裁決，勿用於實盤）
trial_scope: largecap_enhanced   # 不帶 bt: 前綴——框架會自己加（R5）

universe:
  markets: [TWSE, TPEX]
  mktcap_rank_max: 100        # 只在市值前 100 大裡選
  min_adv_twd: 30_000_000
  min_price: 10.0

combine: rank_avg
signals:                       # 與 §3.5 同一組四因子，不另外配適
  - {factor: fundamental.revenue_yoy, weight: 0.25}
  - {factor: price.mom_60d,           weight: 0.25}
  - {factor: fundamental.roe,         weight: 0.25}
  - {factor: price.vol_20d,           weight: 0.25, params: {window: 60}}

selection: {method: top_n, top_n: 30}
weighting: mktcap              # T-123 新增
rebalance: {schedule: monthly, day: MON, execution: next_open}
max_weight_per_stock: 0.25     # 見 §5.4
overlays: []
```

### 5.3 B2「全市場多因子 + 市值加權」`track_b2_broad_capw.yaml`

不限制市值，但改成市值加權，讓權值股在得分高時能真正吃到權重。

與 B1 逐字相同，**只差三處**：
- `universe` 移除 `mktcap_rank_max`（改為全市場流動性篩）
- `selection.top_n: 30 → 50`
- `name` / `description` / `trial_scope: broad_capweighted`（同樣不帶前綴）

### 5.4 `max_weight_per_stock: 0.25` 是事前決定，不得搜尋

0050 的台積電權重約 57%。若我們設 5%，就結構性做空它；若設 57%，
整個策略等於一檔股票。**0.25 是事前寫定的折衷**，理由寫在這裡以防日後被當成配適結果：

- 它讓單一權值股能吃到 **7.5 倍**於等權（30 檔等權 = 3.33%）的權重，足以顯著改變 Beta
- 又保留至少 4 檔的有效分散度下限

**不得為了改善回測而調整此數字。** 若要改，走 DECISIONS.md 開新裁決、
並計為一次新的試驗。

### 5.5 B 軌的強制檢查

1. **Beta 必須列出**。B 軌若 Beta 顯著低於 0.8，代表架構改造失敗
   （仍然結構性做空大盤），此時「輸給 0050」不是選股問題，不得歸因於因子。
2. **追蹤誤差（TE）** 必須列出：策略日報酬 − 0050 日報酬的年化標準差。
3. **必須同時列出「0050 買進持有」本身的曲線**，並在報表明說：
   若策略未勝出，正確結論是「直接買 0050」，不得包裝成其他說法。

## 6. 報表：雙軌回測分析頁

沿用既有管線：`report_bundle.py`（產資料包）→ `build_dashboard.py`（渲染 HTML）。

### 6.1 頁面結構

單一 HTML，離線可開，資料內嵌。頂部**分頁切換**兩軌（不並排——兩軌基準不同，
並排會誘導錯誤比較）。

每一軌的分頁包含：

1. **KPI 列**：CAGR / MDD / Sharpe / 年化周轉，每項下方附**該軌主基準**的同項數值。
   比較值一律從 `bench_stats` 取，**不得寫死在字串裡**
   （曾因寫死導致「TAIEX −34.37%」的錯標，−34.37% 其實是等權宇宙的回撤）。
2. **權益曲線**：策略 + 該軌主基準 + 參考基準（0050 含息／不含息、TAIEX）。
3. **年度長條**：策略 vs 主基準，逐年。
4. **基準對照表**：每個基準一列，附「這個基準代表什麼」的角色說明。
5. **歷年持股**（§6.2）。
6. **方法論表**：成本口徑、宇宙、前視偏差防護、樣本內外、試驗計數、晉升判定。

### 6.2 歷年持股（本次新增的重點）

`BacktestResult` **沒有**歷史部位，只有 `final_holdings` 與 `ledger`。
歷史持股必須由 `ledger` 重建（T-125）：逐筆買賣累加股數，得到每個交易日的部位。

呈現三層，由粗到細：

- **年度摘要**：每年的持股檔數、換手次數、當年貢獻前 5／後 5（代號、名稱、損益）
- **調倉時間軸**：每個調倉日一列，列出當期持股清單，
  **新進標綠、剔除標紅、續抱不標色**——讓人一眼看出換了什麼
- **個股明細**（可展開）：每檔的持有區間、進出價、報酬、期間最大逆行（MAE）

可讀性要求：
- 股票一律顯示「代號 名稱」（名稱取自 `stock_meta`，缺名不得留空、須顯示代號並標註）
- 表格橫向捲動限制在自身容器內（`overflow-x: auto`），頁面本體不得橫捲
- 數字用 `font-variant-numeric: tabular-nums` 對齊
- 紅漲綠跌（台股慣例），與既有頁面一致

## 8. 登記與晉升

### 8.1 試驗計數（**最容易出錯的地方**）

每一次回測都是一次試驗，會進 `research_log` 並影響 DSR。
本規格新增的試驗，**事前**登記如下，執行者不得增加：

**YAML 的 `trial_scope` 不得帶 `bt:` 前綴。** `reporting/research_log.py` 的
`backtest_trial_scope` 回傳 `f"bt:{strategy.trial_scope or strategy.name}"`——YAML 若寫
`bt:smallcap_momentum`，實際登記成 `bt:bt:smallcap_momentum`，與預期的家族對不上（R5）。
既有 `ml_net_h20_m.yaml` 寫的是 `ml_net_h20_turnover`（無前綴），照它寫。

**「執行次數」不等於「DSR 的 trial 數」。** `trials_count` 算的是**同一 scope 內
distinct `params_hash`**，而 `params_hash` 排除 `name`／`description`／`trial_scope`、
包含策略其餘欄位與**成本配置**。由此：

- 同一配置重跑 → 不增加 trial
- 1× 與 0×／1.5× 成本 → `params_hash` 不同 → **各算一個 trial**
- 四個新家族**各自獨立計數**，不會自動與既有 29 筆相加成 47

| trial_scope（YAML 寫法） | 候選 | 成本情境 | 該 scope 的 distinct hash |
|---|---|---|---|
| `ladder_diag` | L1、L2、L3、L4、X1（5 個） | 1×、0× | 10 |
| `smallcap_momentum` | A（1 個） | 1×、0×、1.5× | 3 |
| `largecap_enhanced` | B1（1 個） | 1×、0×、1.5× | 3 |
| `broad_capweighted` | B2（1 個） | 1×、0×、1.5× | 3 |

**L0 不在上表**：它不改配置，scope 仍是既有的 `bt:ml_net_h20_turnover`，
重跑不產生新 hash。它是對照基準，不是新候選。

**1.5× 全成本是 D-038 §5 的晉升條件**（「1.5× 成本後 CAGR／Sharpe 仍 > 0」），
不是可選項；D-059 的先例是「同一候選同一規格，不另計 trial」，但因 `params_hash`
含成本配置，實務上仍會產生一個 distinct hash，故上表據實列出。

**DSR 取哪一組 Sharpe 序列，必須在跑之前寫定**：以候選所屬 scope 內的
distinct `params_hash` 對應的 Sharpe 為序列，樣本長度用該候選自身的 OOS 天數。
不得以「換一個家族名稱」把選擇歷史清零——DSR 的整個目的就是懲罰選擇歷史
（Bailey & López de Prado）。

### 8.2 晉升判定：**研究通過**與**可部署**是兩件事（R2）

先前版本自相矛盾：§1.2／§9 禁止用「輸給 0050」判 A 軌失敗，§8.2 又要求
全部沿用 D-058 的「須勝過 0050」。執行者可依不同條文得到相反裁決。改為兩層：

**第一層 — 研究通過（選股是否加值）**

| 軌 | 判定基準 | 問的問題 |
|---|---|---|
| A | 等權小型宇宙（同宇宙、同等權、不選股） | 在這個池子裡挑股票有沒有加值 |
| B | 0050（不含息） | 這個組合有沒有勝過直接買指數 |

**第二層 — 可部署（值不值得把錢放進去）**

**兩軌都必須通過**，且**都要跟 0050 比機會成本**。A 軌在第一層不以 0050 判定，
不代表配置資金時可以免除這個比較——「小型股選股有加值」與「值得把錢從 0050
搬過來」是兩個不同的問題，兩個都要回答。

沿用 D-038 §5 九條 + D-058。九條逐條映射到兩軌（含「最強線性基準」究竟指哪一條策略）
必須在 T-128／T-129 的完成註記中逐項列出，不得籠統引用。

**股利口徑的限制必須寫在判定旁邊**：策略與基準都不含息只是**價格口徑一致**，
若兩者殖利率不同，總報酬的優劣仍可能與價格報酬相反。故第二層的部署判定
**必須等 T-113（引擎股息入帳）完成**；在那之前，本規格的產出只核可作為
**價格報酬診斷**，不得作為部署依據。

B 軌若通過、A 軌若未通過，兩者互不影響——分軌判定，不得互相背書。

### 8.3 事前登記的方向性假設（一個主張，非多個獨立點）

> 在台股 0.4–0.65% 的來回成本下，**改變宇宙與加權（B 軌）** 對「打敗 0050」的
> 貢獻，大於**改變訊號（換因子或換模型）** 的貢獻。

這個主張可被證偽：若 B1／B2 的 Beta 顯著提升但相對 0050 的超額仍為負，
且 X1 顯示換訊號帶來顯著改善，則本主張被推翻，應回頭做訊號而非架構。
