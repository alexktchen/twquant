# LOOP — 三大閉環

系統的品質不靠一次做對，靠三個會自我修正的迴圈。每個迴圈都有：輸入、閘門（gate）、
產出物（artifact）、回饋路徑。閘門條件全部是可機器判定的，不依賴主觀判斷。

## 1. 研究閉環（策略/因子的生命週期）

```
想法 → 因子規格 → 單因子檢驗 → 組合回測 → 審查閘門 → 模擬倉 → 小資金實盤 → 歸因
  ▲                                                                        │
  └────────────── 歸因結果、失效偵測、新資料 ──────────────────────────────┘
```

| 階段 | 閘門條件（全過才晉級） | 產出物 |
|---|---|---|
| 因子規格 | 寫成 `docs/factors/<name>.md`：假說、公式、資料需求、預期方向 | 因子規格文件 |
| 單因子檢驗 | 對本地因子中性化後 RankIC t-stat ≥ `ic_tstat_screen`(=2) 進候選；IC 衰退半衰期 ≥ 持有週期；與既有因子庫相關 ≤ 0.7 | IC 報告 |
| 組合回測 | 成本後 Sharpe ≥ 1.0；MDD ≤ 20%（與 kill-switch 一致，D-009/REVIEW M8）；年周轉 ≤ 配置上限；deflated Sharpe p < 0.05（計入嘗試次數） | 回測報告 |
| 審查閘門 | 正式上線 RankIC t ≥ `ic_tstat_promote`(=3)；walk-forward 樣本外 Sharpe ≥ 樣本內 50%；參數 plateau（鄰域 Sharpe 差 < 30%） | 驗證報告 |
| 模擬倉 | ≥ 60 個交易日；模擬倉每日權重 vs 研究回測同日權重一致；管線決定性、訊號按時產出率（滑價比 1.5 倍檢核移到實盤階段，模擬倉同碼同資料下該比恆為 1、無意義，REVIEW M9） | 模擬對帳報告 |
| 小資金實盤 | ≥ 60 個交易日；績效落在回測 [5%,95%] 信賴帶；實際/預估滑價 ≤ 1.5 倍 | 實盤歸因報告 |

IC 門檻兩階段（D-006）：初篩 2、上線 3，兩數字放 `configs/risk.yaml` 的
`ic_tstat_screen`/`ic_tstat_promote`，本表與 STRATEGY §1-8 都引用此鍵。
回測 MDD 閘門收緊到 20% 與實盤 kill-switch（回撤 >20% 清倉）對齊，避免信賴帶
在壓力期失真（實盤被截斷、回測沒有）。

**嘗試次數登記**：每一次「跑過回測的參數組合」都要記錄在 `research_log/`
（schema 見 SPEC-002 §4）。deflated Sharpe 的 trials 數從這裡來，
禁止洗掉重來。這是防止過擬合的核心機制。

**降級規則（回饋路徑）**：實盤策略連續 3 個月績效落出信賴帶下緣，或 20 日追蹤
誤差超標 → 自動降回模擬倉狀態並告警；因子 RankIC 滾動 12 個月 t-stat < 1 → 標記
「疑似失效」，進下一次研究週期重新檢驗。

## 2. 開發閉環（AI 實作的品質迴圈）

定義在 [CLAUDE.md](../CLAUDE.md) §2。要點：

- 任務佇列（TASKS.md）→ 規格（SPEC 驗收條件）→ 測試先行 → 實作 →
  機器閘門（`python -m twquant check`）→ 完成定義自查 → 收尾
- 閘門是強制的、自動的、不可協商的。弱模型寫出的錯會被測試與型別攔住，
  而不是靠模型自覺。
- 卡住三輪 → DECISIONS.md 待裁決 → 換任務。人（或高階模型）只處理裁決，
  不處理日常實作。

規格的撰寫規則（讓任何模型可實作）：
1. 每條驗收條件（AC）必須是可寫成測試的具體陳述，含輸入、輸出、精確度
2. 介面用 Protocol/型別簽名寫死，不用散文描述
3. 每份 SPEC 有「範圍外」段落，明確說不做什麼
4. 範例輸入輸出直接放在 SPEC 裡（doctest 風格）

## 3. 營運閉環（每日生產迴圈）

**多波次擷取（D-008/H3/H18）**：資料按可得時點分波，品質閘門逐表在「該表
available_at 之後」才檢核，否則對尚未公布的表天天誤觸發 degraded：

```
16:30 盤後批擷取（價量/三大法人/處置公告/期貨法人）
  → 20:00 訊號 PIT 截點：因子/訊號 → 次日目標權重（融資以 T-1 進）
21:45 晚間批擷取（融資融券 margin_daily）
次日 08:00 broker_trades 批；週六 12:30 TDCC 股權分散批
  → 08:30 盤前檢查（含「昨日 pipeline heartbeat 存在」）→ 09:00- 執行
  → 14:00 對帳 → 17:00 歸因與漂移偵測 → 告警/自動降風險 → 調整風險預算
```

| 步驟 | 閘門/規則 | 失敗行為 |
|---|---|---|
| 資料擷取 | 逐表預期列數（在該表 available_at 之後才檢查）；多波次 | 重試 3 次 → 告警，degraded |
| 品質閘門 | schema 驗證；跨來源交叉核對（三大法人合計誤差 ≤ 0.5%）；缺漏股票 ≤ 0.5%；磁碟空間 | 不過 → 當日不產生新訊號，沿用前日權重並告警 |
| 訊號生成 | as_of=當日 20:00（D-008）；訊號前硬性斷言 latest_date(prices_daily)==今日；因子分布 PSI > 0.25 告警 | 當日資料缺 → raise+CRIT；異常因子當日權重歸零 |
| 盤前檢查 | 帳戶現金/持倉與系統帳一致（任何 ≥1 股或 ≥1 TWD 差異即拒絕，SPEC-006）；昨日 heartbeat 存在；當日處置股過濾 | 不一致 → 禁止下單，人工介入 |
| 執行 | 單股參與率 ≤ ADV（20 日成交額中位數）之 5%（Sleeve C 3%）；漲跌停不追單；分批 TWAP | 未成交部分記錄，不隔日追 |
| 對帳 | 券商回報 vs 系統預期逐筆對 | 差異 → 凍結新單（寫 data/state）+ 告警 |
| 漂移偵測 | 「PaperBroker 影子損益 vs 實盤損益」日度差的滾動 20 日年化**標準差**（tracking error）≤ 3% | 監控寫 REDUCED 旗標 → SPEC-005 狀態機自動轉 REDUCED；連 5 日 → HALTED 待裁決 |

- **dead-man switch（REVIEW M29）**：pipeline 每次成功寫 heartbeat（日期+git hash）；
  獨立 watchdog 於交易日 19:00 檢查 heartbeat 缺失 → CRIT（防主機休眠/排程未觸發
  導致的靜默停更）。錯過執行的 catch-up：當日 22:00 前可補跑，之後標 degraded 沿用前日權重。
- 漂移「自動降風險 vs 建議旗標」的責任鏈：monitoring 只寫旗標到 data/state，
  SPEC-005 狀態機讀旗標後自動轉 REDUCED（REVIEW H16）。

**kill-switch（最外層保險，任何時候優先）**：
- 單日虧損 > 帳戶淨值 3% → 停止開新倉
- 回撤自高點 > 15% → 全部策略降至 50% 風險預算
- 回撤 > 20% → 清倉、停機、等待人工裁決
- 資料品質閘門連續 3 日不過 → 停機

閾值全部在 `configs/risk.yaml`，此處數字為初始值。

## 4. 洞悉閉環（LLM 提案迴圈，SPEC-008）

```
營運/研究閉環的產出物（歸因、漂移、因子健康度、research_log）
  → LLM advisor（週頻）產生結構化提案 → proposals/ (pending)
  → 自動回測驗證（走 §1 研究閉環的同一套閘門）→ validated | rejected_by_gate
  → 人工核准（CLI）→ 模擬倉 60 日 → promoted | demoted
       │
       └── rejected/demoted 的提案與原因回饋進下次 advisor 輸入（不重提測過的東西）
```

規則：
- LLM 永遠只能提案，不能執行；提案不繞過 §1 的任何閘門
- `no_action` 是合法且預設的提案結果——沒有值得改的就不改
- 提案的嘗試次數同樣計入 research_log（deflated Sharpe 的 trials 包含 LLM 提的）
- 模型路由與預算見 MODEL-POLICY.md §3

## 5. 四個閉環的關係

開發閉環保證「程式碼做的是規格說的」；研究閉環保證「規格說的在統計上值得做」；
營運閉環保證「實盤發生的與研究預期一致，不一致就自動收手」；
洞悉閉環讓系統「自己讀自己的報表、自己提出下一輪假說」，但提案仍受研究閉環
的機器閘門與人工核准約束。任何一環的產出物（IC 報告、閘門日誌、歸因報告、
提案紀錄）都是下一輪迭代的輸入——系統的改進不需要任何人記得任何事，
全部由 artifact 驅動。
