# HANDOFF 2026-09-23：第九輪（右尾／飆股）＋ 一個污染所有回測的缺陷

> 起點是使用者的一句話：「我都找整體股市的前段班，這樣注定打不贏 ETF，我想要抓到飆股，
> 有沒有從現在的訊號來預測出飆股的樣子，然後再利用賣出模型來提早獲利」。

## 一分鐘版本

1. **右尾訊號是真的**：模型挑的股票 60 日內漲 ≥ +50% 的比例 **19.55%**，同日全市場 **6.06%**
   ——倍率 **3.23×**，1,005 筆分布在 100 個月，每筆淨期望 **+2.14%**。
   九輪來第一個明確為正的右尾結果，而且把事後探索的規則臂（1.85×）打掉一大截。
2. **容器仍然不行**：三臂回撤 −39.7% ~ −54.1%，全部過不了使用者訂的 35%；
   Calmar 0.26~0.32 還低於既有的 E0（0.67）與 V1（0.73）。
3. **下一步是把右尾訊號放進會減碼的容器**（V1 那一型），不是繼續在滿倉 15 檔上加工。
4. 副產品：**T-168 修掉一個會污染所有回測的缺陷**——引擎不處理股票分割。

判定全文見 [DECISIONS.md](../DECISIONS.md) 的 **D-143 §十一**；登記與修訂在 §一~§十。

## 七條事前預測，錯四條

最有價值的是錯的那幾條：

- **`vol_asym_20` 沒進前十。** 波動特徵確實有用——8 支新因子吃掉 B 臂 **72.4%** 的重要度
  （`atr_14` 37.9%、`parkinson_20` 17.5%），`price.vol_20d`（A 臂第一名、57.8%）**掉出前十**。
  但機制不是我以為的「上下行拆解分辨會動與會漲」，而是 **ATR／Parkinson 把同一件事量得更準**。
- **補維度改善的是風險不是命中率**：B − A 的回撤差 **+14.4pp**（−54.1% → −39.7%），
  但倍率反而低 0.22×。
- **D 規則臂遠輸模型**（1.85× vs 3.23×）——我原本預測它會贏。

## T-168：引擎不處理分割（會污染**所有**回測）

`corporate_events` 有 28 筆 split（adj 0.042~0.5）與 6 筆 reverse_split（2.0~7.0），引擎完全不看。
1:20 分割當天價格掉 95%，D-029 的跳價防護把部位當成資料異常強制出清，記成 −94% 的真實虧損。

**它是不對稱的**：標籤那一側（`attach_adjustment`）早就連乘全部 `adj_factor` 還原了
——模型用乾淨資料訓練、回測吃假虧損。

修正有四層，**少任何一層都不行**：

1. 引擎：分割日在收盤更新之前調整持股、成本股數與持有期高低點，並同步縮放 `last_close`
2. 結果包：新增 `splits` 明細（比照 `dividends`）
3. `backtest/diagnostics.py`：重建部位時併入分割
4. `reporting/trade_journal.py`：同上，並同步調整成本股數

**第 1 層做完會立刻炸**：`ledger 賣超持倉：5314 2025-04-10，持有 11000、賣出 205000`
——引擎把股數調對了，但 ledger 裡沒有那筆變動，所有從 ledger 重建部位的下游都對不上。

修正後：A 臂最大單筆虧損 −91.1% → **−65.5%**、每筆期望 +1.89% → **+2.14%**，
**但回撤一點都沒變**（−54.1%）。假虧損不是回撤的來源。

**已知未修**：宇宙衛生濾網（`max_jump_ratio`）也把分割當成資料異常，會把該檔踢出候選
60 個交易日。同一個缺陷的第二個落點，不在 T-168 範圍。
