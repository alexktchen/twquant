# PRD-003 — twquant 專業平台：每日選股、模型歷程、回測與產業研究

版本：0.2（2026-09-05）；任務：T-200；狀態：產品與工程交接草案，功能尚未實作。
使用者定位：先單人自用，之後再對外開放。產品主線依 [PRD-002](PRD-002-insight-ml-recommendation-platform.md)。
本文件定義平台導覽、畫面、查詢契約與交付順序；不宣告現有模型已可部署。
引用規格：[SPEC-008](specs/SPEC-008-insight.md)、[SPEC-009](specs/SPEC-009-serving.md)、[SPEC-010](specs/SPEC-010-ml.md)、[SPEC-013](specs/SPEC-013-two-track-strategies.md)。

## 1. 核心體驗與資訊架構

每天開站先看到「今天 ML 選了什麼、哪些資訊改變了判斷」。再從同一筆推薦往回查模型怎麼訓練、回測結果與產業證據，往後查推薦的實際觀察結果。
平台不是每天重訓：訓練產生版本，日頻推論使用指定合格版本，洞悉再分析候選；三者的頻率與狀態分開。

| 導覽分組 | 頁面／建議路由 | 主要用途 |
|---|---|---|
| 每日投資 | 總覽 `/overview` | 當日推薦、模型／資料狀態、重大變化、自選提醒 |
| 每日投資 | ML 選股 `/recommendations?date=&model=&bucket=` | 原始名單、洞悉篩選、歷史每日快照 |
| 每日投資 | 我的追蹤 `/watchlists` | 自選、觀察原因、筆記、到期提醒；之後加模擬投組 |
| 市場研究 | 個股 `/stocks/:sid?as_of=&run=` | 圖表、財報、籌碼、推薦理由與歷史 |
| 市場研究 | 產業 `/industries`、`/industries/:id?as_of=` | 資金、成長、廣度、事件與相關候選 |
| 市場研究 | 洞悉 `/insights?as_of=&type=` | 每日摘要、證據、異常解釋、研究提案 |
| 模型研究 | 模型中心 `/models`、`/models/:id` | 模型版本、訓練歷程、樣本外結果、發布資格 |
| 模型研究 | 回測中心 `/backtests`、`/backtests/:id` | 歷史結果、成本、基準、持倉與交易 |
| 營運 | 資料與工作 `/operations?tab=` | 沿用擷取後台，加推薦／訓練／回測工作狀態 |

URL 保存日期、模型、分類、排序和比較 ID；可重新整理、分享深連結及使用瀏覽器上一頁。不能只靠 App.tsx 的本地 page state。
個股跳轉保留推薦 run 和日期，避免「歷史推薦」的標題配上「今天」的理由。使用者切到最新行情時明示已離開原快照。

## 4. 每日 ML 選股中心

- 控制列：交易日、模型、策略、horizon、研究資格、洞悉分類、產業、資料完整度；跨策略分數不直接混排。
- 表格預設欄：ML 排名、股票、產業、原始 score／分位、新進／續留／退出、洞悉分類、主要支持／反對理由、資料時間。
- 次要欄可選：策略曝險、流動性、風險標記、證據數、模型版本。表頭說明分位不是上漲機率。
- 點股票進個股頁；點理由開證據抽屜；點模型到版本詳情；加入追蹤保存當時 run 與原因。
- 日曆只提供已存在的發布版本；補製的歷史 run 明標 `reconstructed`，沒有首次發布紀錄就不能算向前實績。
- 原始 ML 清單和洞悉篩後清單並列成頁籤；排除列與理由保留。洞悉未完成為 pending，不等於 watch 或 exclude。
- 模型日頻推論即使策略月頻調倉也可顯示，但標示「今日分數觀察／尚未到調倉日」，不能把日頻排名當成已成交或新策略訊號。
- 分析截點晚於原始 ML 截點時，列出兩個截點與實際發布時間；可成交起點不能早於最終發布。
- 匯出 CSV 帶日期、模式、model_id、run_id、分類、來源時間；只有使用者按匯出才產檔，內部敏感 metadata 不預設附出。

## 5. 模型中心與訓練歷程

列表每列是一個 training_run，而不是只列成功落地的模型。欄位：目的、模型家族、執行狀態、資料區間、特徵數、完成窗數、OOS RankIC、耗時、資料品質與資格。
執行狀態：queued → running → succeeded／failed／cancelled／interrupted。模型研究資格另為 unreviewed／research／paper／approved／retired／invalidated；失敗 run 可沒有 model_id。

模型詳情頁包含六個頁籤：

| 頁籤 | 資料與互動 |
|---|---|
| 概覽 | 訓練目的、資料／標籤／程式版本、horizon、最近推論、是否有發布資格 |
| 訓練歷程 | 讀資料→組資料集→切窗→逐窗訓練／評估→最終 fit→artifact→驗證；逐步耗時與失敗訊息 |
| 分窗評估 | 各窗 train/test 期間、樣本數、IC、彙總與分布；點窗看詳情 |
| 特徵與資料 | 特徵名、定義、缺值率、版本差異；重要度存在才顯示，不能解讀成因果貢獻 |
| 關聯回測 | 以 model_id／artifact fingerprint 關聯結果、資料可比性及研究裁決 |
| 版本比較 | 配置、標籤、特徵和資料差異；只在相同評估口徑下展示績效差 |

目前 progress callback 只提供完成窗資訊，不能做出不存在的逐 iteration loss 曲線。尚無事件資料的舊模型顯示「歷史 artifact，詳細執行過程未記錄」；不以檔案 mtime 偽造訓練起訖。
新事件契約：run_id、event_seq、stage、started_at／ended_at、completed_units／total_units、fold_id、metrics_ref、sanitized_error。無 total 時使用不定進度，不能做虛假百分比。
training_run_id 表示一次執行；model_id／artifact_fingerprint 表示產物；trial_scope／params_hash 表示試驗。三種數量分開，資料匯入與重新讀報表不增加 trial。
不展示 vault 指標、曲線或摘要。樣本外開發期可被反覆檢視，因此 UI 寫「walk-forward 開發評估」，與封存最終驗證分開。

## 6. 回測中心

列表：策略、模型、區間、成本情境、研究資金、狀態、CAGR／Sharpe／MDD、基準、資料資格。可搜尋／篩選與勾選比較，預設只顯示有效結果但可查看失敗與已失效紀錄。
詳情頁：

1. 摘要：研究問題、配置、資料版本、期間、交易假設、主基準及資格。
2. 績效：策略／基準同起點權益曲線、回撤、年度／月度報酬；數字由結果包與共同後端統計提供。
3. 交易與持倉：調倉時間軸、新進／退出／續留、每日持股、ledger、未成交及成本拆解。
4. 驗證：成本敏感度、walk-forward、適用 DSR、穩健性與門檻逐項證據；沒跑顯示未評估。
5. 方法與產物：成本、整張／零股、含息／不含息、參與率、配置指紋、結果包和相關裁決。

比較前檢查期間、宇宙、基準、成本、資金、成交方式和共同資料表身分。不同策略可能讀不同表，不能只要求總 data_fingerprint 字串相同；檢查重疊表版本並列出非共同來源。
不相容結果可並排查閱，但禁止顯示「勝出」或直接計算單一改善值。A/B 軌主基準依 SPEC-013 分頁呈現；0050 含息／價格指數亦須分清。
80M 是目前研究比較資金，不是使用者建議投入額；實際資金可行性與零股仍接 T-148 的獨立驗證。
舊 GET /api/backtest 涉及現算，新中心優先讀已完成結果包；刷新頁面、展開交易和下載報表不得重跑回測。

## 7. 產業研究與個股洞悉

產業總覽顯示流向、報酬廣度、營收廣度、候選數、持倉曝險與資料涵蓋率；可排序列表和熱圖共用同一份資料。資料範圍不齊時顯示分母、缺失與排除數，不能只呈現看似全市場的總和。
每個產業詳情：產業摘要→趨勢／同業比較→新事件→相關 ML 候選→證據來源。保留分類版本及 as_of，歷史分析不能套用今天的分類而不標示。
廣度、加權方式與窗口需另在 configs／SPEC 定義；前端不自行選權重。第一期沿用官方產業分類；AI 供應鏈等主題群組屬另一套有版本的映射，不能憑模型臆測補齊。
洞悉卡固定提供已知事實、支持／矛盾證據、影響期間、資料缺口、來源與更新時間。LLM 摘要失敗仍保留量化面板。
個股页沿用 stock/ 元件，上方新增「入選與風險摘要」，下方提供「關聯產業／推薦歷史／原始證據」。企業消息與基本面只記當時可得版本；LLM 內建知識不當證據。
以股票與 date/run 為界的查詢提供「為何入選／退出」「與同業差異」「哪些證據矛盾」；透過白名單資料查詢，無任意 SQL、shell 或交易權限。

## 8. 跨頁資料關聯與 API 草案

```text
training_run → model_version → backtest_run → validation_record
                    ↓                         ↓
             recommendation_run ← model_release（核准及有效期間）
                    ↓
        recommendation_item → insight_run → evidence_bundle
                    ↓
         outcome（到期才有）→ 第二層訓練候選資料集
```

歷史頁所有連結以 ID 固定版本；URL 的 model_id 不足以授予發布權。daily 推論選擇經核准且在有效期內的 release，不能直接沿用「最新 train_end 的模型」作發布判定。

| 建議 GET 端點 | 來源／用途 |
|---|---|
| `/api/platform/overview?date=` | 發布快照摘要、資料狀態與最近工作 |
| `/api/recommendation-runs`、`/:id`、`/:id/items` | 日曆／版本列表、候選與發布資訊；服務端分頁 |
| `/api/models`、`/:id` | 模型 metadata 投影、release 資格、關聯回測 |
| `/api/training-runs`、`/:id`、`/:id/events?after_seq=` | 全部執行與增量事件，包含失敗紀錄 |
| `/api/backtest-runs`、`/:id`、`/:id/positions`、`/:id/trades` | 結果包索引、持倉重建與 ledger 分頁 |
| `/api/industries?as_of=`、`/:id` | 產業聚合與引用；既有 sector-flows 可作一個輸入 |
| `/api/insights/:id`、`/api/evidence-bundles/:id` | 分析與可公開證據，不回傳秘密或私人原始帳務 |

以上是待寫入 SPEC 的新契約，並非已存在 API。統一回應包含 schema_version、as_of、generated_at、data_status、source_version、warnings、pagination。
資訊截點 `information_cutoff`、分析完成 `analysis_completed_at`、發布 `published_at` 分開；重建樣本另有 `reconstructed_at`，不能把它回填成歷史首次發布。
大表服務端排序／分頁；query key 包含 run/model/date/filter，切換後取消過期請求，防止模型 A 標題配模型 B 資料。
舊 artifact 由資料／reporting 層白名單根目錄匯入索引並驗 hash；API 接受 ID，不接受任意檔案路徑。受損或不支援版本要留錯誤紀錄，不靜默跳過。
PostgreSQL 衍生讀模型可重建；工作事件、原始推薦、使用者筆記與人工審核需要持久化備份。大結果包保存在 artifact 儲存，列表 API 不掃整個資料湖。

## 9. 視覺與互動交接

各元件接收固定 run/model/date 與顯式 loading/error/status props；頁面不內嵌未公開的模型、資料庫或套件名稱當產品文案。
表格 Enter 開詳情、列內其他操作使用獨立按鈕；Esc 關抽屜並還原焦點。側欄有 aria-current、頁面有 skip link、表頭有 aria-sort；進度有文字和 aria-live，不能每次輪詢朗讀完整日誌。
標題與公司名最多兩行，截斷可展開；ID 視覺縮短但可複製完整值；證據全文在詳情展開。金額 TWD、比率顯示格式、股數單位由共用 formatter 統一。

## 10. 所有頁面必須具備的狀態

| 狀態 | 顯示與可用操作 |
|---|---|
| 載入中 | 與最終配置同尺寸的 skeleton，不顯示假數值 |
| 沒有資料 | 區分「未產生」「尚未整合來源」「合法零候選」，提供適用的下一步 |
| 分析中 | ML 清單可讀、洞悉 pending；逐股成功／失敗狀態，不把缺席當排除 |
| 過期資料 | 原日期常駐、最近成功 run 可查；不以今日日期包裝舊快照 |
| 執行失敗 | 已完成步驟、失敗階段與可讀原因；手動重試仍依權限與既有工作邊界 |
| 結果失效 | 保留圖表與歷史記錄，但加原因、受影響版本與重驗狀態；不列入有效績效比較 |
| LLM 離線 | 量化名單與原始證據可用；洞悉缺席原因明示 |

## 12. 上線順序、效能與裁決

第一個可用版本完成 C0＋C1＋C2 的研究模式＋C3：每天能看名單，也能查模型歷程與回測來源。下一版補 C4 的產業／洞悉，再開始 C5 的向前資料累積；是否啟動第二層訓練依 D-066／D-080。
自用建議效能目標：索引列表 API p95 ≤500ms、首屏有用內容 ≤2s；用固定資料集與快取狀態量測，屬新目標而非目前實績。大量交易資料分頁，繁重運算留在 worker，完成事件更新讀模型。
工作狀態先輪詢（間隔由配置注入），有需求再加 SSE；不新增與現有排程互相搶跑的 scheduler。同模型／日期工作使用 idempotency key 和持久化狀態，重啟可標 interrupted，不能永遠 running。
原始日誌去除秘密；證據与使用者資料按 owner 授權。單人版亦不能把新增訓練／檔案路徑操作暴露成未驗證公開 API。
待裁決入口：[D-080](../DECISIONS.md)。本輪已確認方向是建平台與洞悉回饋規劃；訓練按鈕、第二層訊號及正式發布權限不由這份草案直接開啟。
訓練與回測能成功執行，不代表投資結果有效；公開版再增加會員、通知與資料授權等需求，不阻擋先完成自用閱讀流程。

## 13. 全面重構範圍與操作旅程（使用者追加）

全面重構涵蓋現有個股頁及資料後台，不只新增頁面。交付分成畫面／操作／資料接線三項，各自驗收，不以文件或可點原型替代已上線功能。

| 舊體驗 | 新體驗 | 遷移規則 |
|---|---|---|
| 單一個股頁同時塞選股、策略池和研究 | 選股中心負責找股；個股詳情負責研究；保留日期與來源 run | 現有因子篩選器搬到選股中心的「條件選股」，不能改名成 ML 推薦 |
| 大量面板往下捲 | 概覽／價量／籌碼／基本面／產業／推薦歷史頁籤，證據抽屜補細節 | 原資料和圖表定義沿用，排列與操作重新設計 |
| 擷取按鈕、缺口與工作紀錄混排 | 資料概覽／來源涵蓋／工作中心分頁，只有適用列提供操作 | 保留既有白名單和併發限制，新工作種類另有契約 |
| 全站日期與單頁篩選容易混用 | ContextBar 顯示目前日期／模式／模型；頁內篩選保持可見 | 進歷史快照鎖 run，切最新時明確清除歷史上下文 |
| 自選只在個股頁角落 | 全站可加入追蹤、獨立清單和研究筆記 | localStorage 既有清單需可匯入／去重；伺服器保存另依 D-080 |
| 回測／訓練只在終端或分散報表 | 可搜尋歷程、可比較版本、可定位失敗階段 | 原始 artifacts 仍為依據，頁面刷新不啟動重跑 |

核心操作旅程：

1. **每日選股**：首頁選日期與模型 → 查看新增／續留 → 點理由看證據 → 點股票看個股 → 加入追蹤並記錄原因 → 回到原列表位置與篩選。
2. **模型研究**：模型列表 → training_run 詳情 → 分窗與資料版本 → 關聯回測 → 查看差異與驗證限制 → 回到原模型；訓練進度變化不清除使用者目前閱讀位置。
3. **回測判讀**：選結果 → 檢查口徑 → 比較曲線／回撤 → 點調倉日看持股 → 點股票回到該日個股上下文 → 回到原交易頁與頁碼。
4. **產業研究**：產業總覽 → 產業詳情 → 看成長／資金／事件及缺口 → 同業比較 → 篩出本產業 ML 候選 → 加入追蹤；每步保留分類版本與日期。
5. **失敗處理**：首頁異常 → 工作詳情 → 失敗階段與診斷 → 查對應資料來源 → 依現有權限重試；重試建立新 attempt，保留前次紀錄。

重構交接需提供：桌面與手機線框、共用 token／元件、上述五條旅程、loading／empty／error／stale 狀態，以及舊網址／自選資料的相容方案。
驗收補充 AC-10：回到上一頁保留篩選、排序、分頁與選中列；切換日期或模型後不顯示舊身分的圖表；圖表具表格替代資訊，鍵盤可完成主要旅程。
實作前端目錄建議為 app/（殼層與路由）、features/recommendations/、models/、backtests/、industries/、insights/、watchlists/、operations/，共用元件与資料 hook 各自集中；依切片搬遷，單個實作任務仍遵守 repo diff 範圍限制。
設計預覽只用明標示意資料驗證導覽和閱讀次序，不連資料庫、不執行訓練、不生成真實推薦；最終視覺與資料接線仍要在既有前端逐步實作驗收。

## 14. 個股 K 線與推薦日標記（使用者追加）

從任何候選清單點開股票，個股頁首屏即有 K 線與成交量，推薦理由接在圖下方。沿用專案 `frontend/src/charts.tsx` 的 **TradingView Lightweight Charts 5.2**（lockfile 為 5.2.0），共用 `CandleChart` 增加可選的推薦事件輸入；不更換行情來源。既有均線與副圖能力保留，推薦標記使用 v5 的 `createSeriesMarkers`，不使用舊版 `series.setMarkers`。參考：[官方標記 API](https://tradingview.github.io/lightweight-charts/docs/api/functions/createSeriesMarkers)、[官方入門與署名說明](https://tradingview.github.io/lightweight-charts/docs)。

### 畫面與操作

- 上方：股票身分、日 K／週 K、區間、原始／還原價、目前推薦版本。預設日 K、原始價；還原方式與資料截止時間常駐。
- 主圖：可拖曳、縮放的 K 棒，台股紅漲綠跌，十字線顯示日期及 OHLC（TWD）；成交量在同步時間軸的副圖，單位股。
- 事件：ML 原始入選用圓點，洞悉精選推薦用向上箭頭，觀察／排除用具文字的獨立標記；同股多次推薦完整保留。「ML 入選」不能自動變成正式推薦。
- 點推薦箭頭或下方日期清單，顯示該次發布時間、模型／洞悉版本、原始名次與當時理由；「定位推薦日」將該日置於可視區，「查看全區間」重設視窗。可切換顯示標記。
- 推薦事件清單可用鍵盤操作，OHLC／成交量有表格替代。手機保留圖表價格軸、日期軸和事件清單；切股或離頁清除舊圖表事件，避免標到另一檔股票。
- 圖表載入失敗時保留事件清單與行情表並顯示錯誤。沒有推薦紀錄時仍顯示行情，不補造標記；只有原始 ML 候選時只顯示入選事件。

### 時間與事件契約草案

每筆事件保存 `event_id`、字串 `stock_id`、`kind`、`recommendation_run_id`、`model_id`、`insight_run_id`（可空）、`published_at`、`as_of`、`bucket`、`rank`、`reason_ref`、`mode`、`earliest_action_at`（未確定則 null）。`published_at`／`as_of`／`earliest_action_at` 均為 Asia/Taipei tz-aware timestamp；圖表 `session_date` 為交易日日期字串，由供應層依交易日曆建立映射。事件不以取得資料當天或現在的分類覆蓋舊紀錄。

推薦日依實際發布日期標記，與資料基準日分開。例如 08/24 18:30 盤後發布，箭頭標在 08/24 並明示盤後發布；不能宣稱以當日收盤價成交，最早可交易時點需另依策略及下一個實際可交易時段決定。休市或個股停牌當日沒有 K 棒時，事件仍保留原發布時間並出現在事件清單；在下一個有 K 棒的交易日顯示「前次非交易日發布」的定位標記，說明映射日期，禁止套件自行貼到前一根 K 棒。尚無下一根行情時只顯示待定位事件。

歷史快照預設只顯示當時可得的行情與事件；使用者另切「發布後走勢」才顯示後續價格，推薦理由仍固定原版本，後續行情不能回流到歷史判斷。週 K 標記只映射到所屬週，詳情仍顯示原日與完整時間；同日多事件先按時間排序、分組顯示筆數，展開保留所有 event_id。重複 event_id 不新增箭頭。事件需先依 stock_id、模式、模型及上下文篩選，再交給圖表。

價格線不以推薦當日收盤價冒充成交價；切換還原方式會更新全部 OHLC 與價格標線，事件的發布時間保持不變。圖表資料由既有 API／供應層提供，不在前端重算研究 PIT 或交易日曆。正式產品保留 TradingView 署名與連結，依套件 NOTICE 帶入版權告知。

**AC-11（待正式實作測試）**：點列表個股可見真實 K 線與成交量；推薦標記與該 stock_id／run 的發布事件一致；盤後、休市、停牌、同日多次、重複 ID、無推薦、切股、深淺色及手機均有驗收案例；歷史模式不顯示未來事件；週 K 仍可查看精確推薦日；圖表標記與事件表格一致，定位／縮放／顯示切換及跨頁返回可操作。

本輪互動預覽已使用實際 Lightweight Charts 5.2.0 渲染日 K／量與事件，行情及推薦均明標示意；預覽不代表正式 API、週 K、還原價或歷史 PIT 接線已完成。
