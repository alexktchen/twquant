## 四、我犯的錯（下一個 session 不要重犯）

**量錯東西或拿 A 的量測推論 B**——這類錯不會讓程式報錯，只會讓結論悄悄變反：

1. **把「基礎率」當成「模型優勢」**（D-140 §八）。高流動性股票的無條件平均報酬確實較高，
   但使用者買的是「模型挑的那檔」，該看分層 IC。第八輪因此整輪白跑。
   **提議實驗前先量一次分層 IC，就不必跑。**
2. **診斷統計量把「兩邊都沒碰」算進「先跌」**（D-130 §〇）：+10.8pp 被算成 −21.5pp。
3. **判定腳本的回撤比較方向寫反**：`mdd <= -0.25` 會讓愈深的回撤愈容易過，基線 −41.4% 也會「通過」。
   修法附了健全性檢查：基線若被判成達標就 raise。
4. **逐筆統計用在「只有停損」的策略上**：已結束交易全是輸家，R5a 報出勝率 3%、同份結果年化 +15.6%。
5. **提議新實驗前沒查既有結果**：「E0 ＋ 波動度目標化」早由 `lw_mg3_voltgt` 做過（D-133）。
6. **跑重工作時同時跑閘門測試** → 把 PG 連同 Docker 壓垮（2026-09-22）。WAL 復原完整、資料未失。
7. **字串修補不加斷言**：`broker_factor_ic.py` 的因子清單替換沒生效，跑出來是舊清單。

**工程上的教訓：**
- `ewm_mean` 是無限記憶——被裁切歷史後數值會變（RSI 差 28.3）。EWM 因子 `lookback_days` 要宣告到殘留低於浮點精度（250）。
- `upsert` 的 staging 暫存表是 `ON COMMIT DROP`——整批放同一交易第二批就撞名。**每批各自提交。**
- `anchor_invariant` 旗標全 repo 沒有程式在檢查它。整批補算前要**實際抽樣比對**逐日與整批結果。
- 同分過多的因子會讓 Spearman 回 NaN，**一個 NaN 污染整個平均**——IC 計算要濾 NaN。
